# PLCFlow v0.2 — PLC I/O and TON Runtime

v0.2 moves PLCFlow from a compiler-only prototype toward a small automation runtime.

## Implemented

- IEC 61131-3-style direct BOOL addressing with `AT %I<byte>.<bit>` and `AT %Q<byte>.<bit>`.
- Input process image (`%I`) copied into program memory at the beginning of every scan.
- Output process image (`%Q`) updated from program memory at the end of every scan.
- Inputs are read-only from Structured Text and produce diagnostic `PLCF1012` on assignment.
- `TON` on-delay function block with `IN`, `PT`, `Q`, and elapsed time (`ET`) runtime state.
- TIME literals: `T#500ms`, `T#2s`, and `T#1m`.
- Deterministic configurable scan duration in the virtual PLC runtime.
- CLI input injection and multi-cycle execution.

## Example

```iecst
PROGRAM ConveyorControl
VAR
    StartButton AT %I0.0 : BOOL;
    StopButton  AT %I0.1 : BOOL;
    Motor       AT %Q0.0 : BOOL;
    StartDelay : TON;
END_VAR

StartDelay(IN := StartButton AND NOT StopButton, PT := T#100ms);
Motor := StartDelay.Q;
END_PROGRAM
```

Run ten 10 ms scan cycles with the start input active:

```powershell
dotnet run --project .\src\PLCFlow.Cli -- .\examples\conveyor\conveyor-v02.st --run --input %I0.0=true --cycles 10 --cycle-ms 10
```

After 100 ms the TON output `Q` becomes `TRUE`, which drives `%Q0.0` through `Motor`.

## LLVM limitation in v0.2

The LLVM backend still supports the scalar BOOL/INT subset from v0.1. TON function blocks and member access are executed by the virtual PLC runtime but are not yet lowered to LLVM IR. PLCFlow reports this explicitly rather than silently generating incorrect IR.
