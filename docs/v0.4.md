# PLCFlow v0.4 — LLVM to WebAssembly Execution

v0.4 turns the LLVM backend into an executable WebAssembly path rather than an inspection-only artifact.

## Pipeline

```text
Structured Text (.st)
  -> Lexer / Parser / AST
  -> Semantic analysis
  -> LLVM IR
  -> clang --target=wasm32
  -> WebAssembly (.wasm)
  -> Node.js WebAssembly runtime
```

## WebAssembly ABI

PLCFlow emits a small explicit ABI so a host can drive a virtual PLC cycle without knowing LLVM memory layout:

- `plc_set_cycle_ms(i32)` — configure scan-cycle duration.
- `scan_cycle()` — execute one PLC scan.
- `plc_set_<InputName>(i32)` — set a mapped PLC input.
- `plc_get_<VariableName>() -> i32` — read BOOL/INT variables.
- `plc_get_<TimerName>_Q() -> i32` — read TON done output.
- `plc_get_<TimerName>_ET() -> i32` — read TON elapsed time in milliseconds.
- `plc_get_<TimerName>_PT() -> i32` — read TON preset time in milliseconds.

BOOL values cross the host boundary as `0` or `1` so the ABI maps cleanly to WebAssembly's integer types.

## TON lowering

TON instances are lowered into LLVM globals for `IN`, `Q`, `ET`, and `PT`. Each `scan_cycle()` increments `ET` by `plc_cycle_ms` while `IN` is true, clamps elapsed time at `PT`, resets `ET` when `IN` becomes false, and derives `Q` from `ET >= PT`.

## CLI

Emit a WebAssembly module:

```powershell
dotnet run --project .\src\PLCFlow.Cli -- .\examples\conveyor\conveyor-v02.st --emit-wasm conveyor.wasm
```

Compile and execute the same module through Node.js:

```powershell
dotnet run --project .\src\PLCFlow.Cli -- .\examples\conveyor\conveyor-v02.st --run-wasm --input %I0.0=true --cycles 10 --cycle-ms 10
```

Expected final state for the conveyor example:

```text
%Q0.0 = True
StartDelay: Q=True, ET=100ms, PT=100ms
```

## External toolchain

WebAssembly emission requires `clang` with WebAssembly support. `--run-wasm` additionally requires Node.js. Both executables must be available on `PATH`.
